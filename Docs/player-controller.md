# 本地玩家控制器

独立运行 `Knight-Client/Scenes/PlayerSandbox.tscn`，无需登录或启动服务端。保持原启动场景不变。

- 在 Godot 编辑器中打开此场景，按 **F6（运行当前场景）**。F5 保留原项目启动流程。
- WASD：移动；鼠标：瞄准；左键：主操作；Q：切换武器；Space：技能。
- 主操作默认攻击。靠近交互测试台后，勾选右上“允许交互（测试条件）”，主按钮才变为交互。此条件仅为验证切换机制，不定义正式玩法的切换条件。
- 一次按压锁定操作类型：按住攻击走进测试台范围不会中途变成交互；松开再按才切换。交互每次按下仅触发一次。
- 点击“切换键鼠 / 触屏”测试摇杆和共用主按钮，切武器、技能也有触屏按钮；移动端默认触屏。
- 练习靶用于自动瞄准。攻击显示示意射线，步枪/散弹有不同的射线与间隔；技能显示扩散光环并演示 3 秒冷却。测试台可点亮/关闭。
- 右侧可切换死亡状态和重置出生位置。死亡后禁止操作。
- 所有射击、切武器、技能和交互效果都是本地测试反馈，尚未实现伤害、背包或正式技能系统。

## 职责

| 类型 | 职责 |
| --- | --- |
| `PlayerCommand` | 一次模拟步的输入数据，使用 Godot 像素坐标及弧度 |
| `PlayerInputBuffer` | 输入状态、摇杆死区、固定速度归一化、交互边沿缓存 |
| `PrimaryActionState` | 默认攻击、显式交互许可、按压期间模式锁定与交互边沿 |
| `LocalPlayerInput` | 键鼠/触屏适配、失焦与启停处理、向移动层提供输入 |
| `PlayerAim` | 查找 `attackable` 分组中最近的可见目标 |
| `PlayerMotor` | 30Hz 固定步长移动、碰撞和贴墙滑动、死亡停控、传送 |
| `PlayerPresentation` | 根据移动和朝向切换待机、行走、死亡帧 |
| `PlayerCamera` | 本地跟随和房间边界 |
| `PlayerSandbox` | 测试房间组装，连接输入与角色，不进入正式流程 |

## 接入约定

`PlayerMotor.InputSource` 每次模拟步取一次命令，未提供时使用 `Command`。`Simulate(command, seconds)` 是移动入口，后续预测重放复用此入口。当前为即时本地模拟，没有网络序号、待确认队列和服务端校正。

默认速度 96 像素/秒、脚部圆形碰撞半径 5 像素，属于本地测试参数；正式角色配置到像素速度的单位映射、地图碰撞数据与服务端一致性，留到联机接入时明确。当前不使用这些参数替代权威配置。

摇杆模长不超过 0.2 视作死区，死区外输出单位方向，按需求采用固定移动速度。角色在碰撞层 2，阻挡地图在碰撞层 1。移动与瞄准相互独立。

自动瞄准目标加入 `attackable` 分组，死亡时移出；没有目标保持上次朝向且不输出攻击。场景切换或结算前调用 `LocalPlayerInput.SetEnabled(false)` 清理输入；传送使用 `PlayerMotor.Teleport` 清理移动累计时间。生命值归零由角色业务设置 `Alive = false`。

技能与切武器通过独立事件接入测试场景。正式攻击冷却、弹体、伤害、受伤反馈和拾取业务后续由各自模块实现，不加入移动类。

## 验证

运行 `Knight-Client/Scenes/Tests/PlayerSmoke.tscn` 自动验证固定步长、归一化、停止、死亡、传送、墙体阻挡、滑墙、输入边沿和自动瞄准。失败会记录错误并以非零退出码结束。

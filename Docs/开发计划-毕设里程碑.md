# Knight 毕设阶段开发计划（里程碑版）

> **定位**：面向本科毕业设计“稳过一辩、论文有深度、演示不翻车”的落地开发计划。  
> **核心策略**：**核心做深**（服务端权威 30Hz 模拟、低延迟预测校正与插值、弱网实验、核心地牢战斗）+ **外围轻量化堆量**（多角色/武器、蓝币养成、排行榜、B/S 运营管理后台）+ **先打通端到端闭环再迭代**。  
> **关联文档**：[SRS-需求规格说明书.md](./SRS-需求规格说明书.md) · [protocol.md](./protocol.md) · [knight.proto](../Knight-Proto/knight.proto)

### M1：最小联机房间与服务端权威移动（打通端到端主干）
**目标**：两个客户端在大厅组队开局后，进入同一战斗房间并能实时看到彼此移动。

- **服务端任务（Go）**
  - [ ] 新增 `internal/world`（战斗世界与地牢房间实例），接入现有 `internal/tick`（30Hz 固定步长）与 `internal/lobby`。
  - [ ] 实现开局流转：`StartGame` → 下发 `GameStart` & `RoomTransition` → 收到全部 `RoomLoaded` 后激活房间。
  - [ ] 消费 `InputBatch`（消息 97），按固定步长推进玩家位置，加入矩形墙体 AABB 碰撞限制。
  - [ ] 按 15Hz 广播 `Snapshot`（消息 96），包含玩家位置、朝向、状态、最后确认输入序号 `last_processed_input_seq`。
- **客户端任务（Godot C#）**
  - [ ] 新增联机战斗流程（`ProcedureBattle`）与首张战斗房间场景，复用现有 `PlayerMotor` / `PlayerCamera` / `GameHudView`。
  - [ ] 接入输入上报（30Hz 打包 `InputBatch`）与快照接收，驱动本地与远端玩家实体生成/销毁/位置更新。
- **验收标准**：本地双开两个 Godot 窗口，完成“登录 → 建房/进房 → 准备 → 开局 → 互相看到实时移动且不穿墙”。
- **论文价值**：系统核心架构图、服务端固定 Tick 循环与权威移动设计。

---

### M2：低延迟同步深化与可视化调试面板（论文核心技术亮点）
**目标**：把“低延迟网络同步”做深、做直观，既能支撑论文核心章节，又能现场一眼向老师演示技术含金量。

- **客户端任务**
  - [ ] **本地玩家客户端预测 + 状态校正（Reconciliation）**：本地立即响应输入并缓存未确认输入；收到快照后比对权威位置，偏差超阈值时回滚并重放未确认输入，小偏差做平滑纠偏。
  - [ ] **远端实体快照插值（Interpolation）**：维护快照缓冲队列（如 100ms 插值延迟），对远端玩家/后续怪物做线性插值，消除 15Hz 快照造成的卡顿感。
  - [ ] **答辩演示用 HUD 监控悬浮窗（可折叠）**：实时显示 `FPS`、`RTT (ms)`、`丢包率`、`预测校正次数/秒`、`平均位置误差`，并提供**“开启/关闭客户端预测”**与**“开启/关闭远端插值”**实时切换开关。
- **服务端/网络层任务**
  - [ ] 在 KCP 封装层增加**可控弱网注入器**（支持运行时配置人为延迟 ms、抖动 ms、丢包率 %），用于实验与现场对比演示。
- **验收标准**：在人为注入 `150ms 延迟 + 3% 丢包` 时，打开预测与插值后操作跟手、画面平滑；关闭开关后可肉眼看到明显延迟与卡顿对比。
- **论文价值**：客户端预测、状态校正、快照插值核心算法与时序图（论文最硬核的一章）。

---

### M3：核心战斗、主动技能与程序化地牢闭环（核心玩法深化）
**目标**：完成一局完整可玩的 2～4 人合作地牢射击体验，打通战斗、技能、基于预制房池的随机地牢与结算写库。

- **服务端任务**
  - [ ] **权威战斗系统**：武器冷却校验、多弹道类型（单发/散射/连发/范围伤害）、圆形/AABB 碰撞判定、伤害与死亡计算、广播 `EntitySpawn` / `EntityDespawn` / `DamageEvent`。
  - [ ] **主动技能框架**：服务端权威技能冷却与触发校验，支持不同角色的主动技能（如冲刺闪避、护盾/无敌、范围爆发、群体治疗等）并同步状态。
  - [ ] **程序化地牢生成（预制房间池模式，类《死亡细胞》）**：
    - 服务端基于随机种子（Seed）从预制房间模板池中按规则生成地牢序列/分支拓扑（出生房 → 多个随机普通战斗房 / 补给宝箱房 / 精英房 → Boss 房），保证房间不重复且必达 Boss 房；
    - 先用少量模板跑通流程，再扩充至 8～12 个风格/布局各异的预制房间模板。
  - [ ] **基础怪物与 Boss AI**：先跑通近战怪、远程怪和首个 Boss（有限状态机 + 至少 2 种攻击模式 + 血量阶段切换）。
  - [ ] **道具与房间推进**：实现回血/增益道具掉落与拾取（`ItemPicked`）；清光当前房间怪物解锁出口（`DoorState`）；全员进入出口触发房间切换。
  - [ ] **对局结算与持久化**：Boss 死亡触发 Victory，全员阵亡触发 Defeat；汇总击杀、造成/承受伤害、耗时、随机种子、角色与武器快照写入 MySQL `matches` / `match_players`，下发 `GameResult`。
- **客户端任务**
  - [ ] 搭建预制地牢房间模板库、小怪与 Boss 预制体、技能/子弹/受击/回血表现与音效，以及简易地牢小地图/进度指示。
  - [ ] 接入自动瞄准（触屏模式）、鼠标瞄准（桌面模式）、技能按键（`Space` / 触屏技能键）、结算界面（`GameResultView`）与历史战绩查询列表。
- **验收标准**：双开每次开局都能生成不同组合的地牢房间，完整打通并击败 Boss 触发胜利结算，且在大厅查到写入 MySQL 的历史战绩。
- **论文价值**：**基于预制房间池与图拓扑的程序化地牢生成算法**、服务端权威战斗与技能框架、Boss 状态机建模。

### M4：玩法内容扩充与局外养成（做厚可玩性与功能量）
**目标**：基于 Luban 数据驱动与服务端行为组件组合，低耦合地扩充角色、技能、武器、敌人库，并补齐局外养成闭环。

- **玩法内容扩充（数据驱动为主，避免硬编码堆砌）**
  - [ ] **多角色与专属主动技能**：3～4 个可选角色，各自拥有不同基础属性与专属主动技能（如骑士-双持/火力强化、游侠-翻滚闪避、牧师-治疗光环、法师-范围技能）。
  - [ ] **多武器库**：6～8 把差异化武器（通过 `WeaponConfig` 配置弹道、射速、散射、穿透/爆炸、后坐力等，涵盖步枪、霰弹枪、狙击枪、冲锋枪、发射器/激光等类型），支持房间准备页切换与局内宝箱/掉落更换。
  - [ ] **多敌人与多 Boss 库**：5～6 种差异化普通怪（近战追击、远程狙击、散射炮台、冲锋/自爆、召唤/辅助等）+ 精英词条变体 + 2 种机制不同的 Boss。
- **局外业务闭环**
  - [ ] **蓝币经济与角色养成**：通关/结算发放蓝币；大厅增加“角色/商店”界面，支持用蓝币解锁新角色与升级角色等级（服务端用 MySQL 事务保证余额原子扣减）。
  - [ ] **全服排行榜**：基于 `matches` 表提供通关最短耗时榜 / 历史总击杀榜接口与客户端排行榜页面。
  - [ ] **房间内简易聊天**：在 `knight.proto` 追加聊天消息，支持等待房间内发文字消息。
- **验收标准**：从“注册 → 选角/选枪 → 随机地牢联机战斗（多怪/多武器/技能）→ 赚蓝币解锁升级 → 上排行榜”形成高完成度网游闭环。
- **论文价值**：数据驱动配置管线（Luban）、组件化/策略化武器与 AI 扩展架构、MySQL 事务一致性设计。

### M5：游戏运营管理后台（B/S 管理子系统）
**目标**：顺带补齐 Web 运营管理后台，以极低架构成本大幅提升系统的完整性与答辩展示效果。

- **技术选型（最省力方案）**
  - **后端**：直接复用 `Knight-Server/internal/httpapi`，新增 `/api/admin/*` 接口 + 管理员登录鉴权，**直接共享 MySQL `store` 与内存中的 `lobby/session/world` 状态**。
  - **前端**：轻量 Web 管理台（Vue 3 + Element Plus + ECharts，打包后可由 Go 静态托管，保持单进程部署）。
- **4 个核心页面**
  - [ ] **数据概览（Dashboard）**：注册总人数、当前在线人数、活跃房间数、服务端实时 Tick 耗时、对局胜率与武器使用率 ECharts 图表。
  - [ ] **玩家管理**：分页查询、按 UID/昵称搜索、查看资产与持有角色、支持管理员**调整蓝币 / 封禁与解封账号**。
  - [ ] **对局与实时房间**：历史对局列表与单局明细弹窗；实时运行中房间监控列表（支持管理员**强制关闭异常房间**）。
  - [ ] **系统配置与弱网控制台**：只读展示角色/武器/怪物基础配置；支持在线热修改**服务端运行时参数**（开局最少人数、蓝币奖励倍率、**全局弱网模拟延迟/丢包开关**）。
- **验收标准**：浏览器登录后台能实时看到在线玩家与房间、查到最新对局、修改蓝币/弱网参数并在游戏客户端立即生效。
- **论文价值**：C/S + B/S 混合架构亮点、系统监控与数据可视化章节（截图极其加分）。

### M6：弱网量化实验、跨平台验证与答辩准备
**目标**：产出论文必需的实验数据图表，并消除答辩现场演示的一切不确定性。

- **任务清单**
  - [ ] **弱网对比实验**：分别在 `0ms / 50ms / 100ms / 200ms` 延迟与 `0% / 1% / 3% / 5%` 丢包组合下，采集并导出 CSV：有无客户端预测的位置误差、校正次数、客户端帧率、服务端 Tick 稳定性，用 Python/ECharts 绘制论文折线图。
  - [ ] **PC 本地双开一键演示脚本**：准备一键脚本（`docker compose up -d` + 启动服务端 + 打开 Web 后台 + 双开两个 Godot PC 窗口），确保答辩现场完全不依赖教室 Wi-Fi。
  - [ ] **Android 真机验证与录屏**：安装 Godot 4.7.2 .NET Export Templates，打一版 APK 在手机上录制 1 分钟触屏摇杆游玩视频放进 PPT（证明跨平台目标达成，现场不赌真机连网）。
  - [ ] **Docker 一键部署验证**：验证 `Knight-Server/docker-compose.yml` 全量容器化构建启动无误。

## 三、防烂尾红线与保底交付策略

### 明确不做（严格守住边界，避免陷入泥潭）
- ❌ 纯瓦片级从零随机挖洞生成（容易产生死路/穿模；采用**预制房间池 + 图拓扑随机拼接**替代，效果好且算法同样好写论文）
- ❌ 复杂多边形物理引擎同步（服务端坚持 AABB + 圆形碰撞）
- ❌ 全世界状态的 Rollback Netcode（只做本地玩家移动预测校正 + 远端插值）
- ❌ Web 后台在线编辑并热更 Luban 二进制表（后台只展示静态表 + 热改服务端运行时参数）
- ❌ 断线重连战局恢复、好友系统、复杂反作弊、跨服匹配

### 保底交付线（如果临近答辩时间紧张）
- **最低稳过线**：**M0 + M1 + M2 + M3 + M5（概览/玩家/对局 3 页）+ M6（弱网实验数据）**。
- **高分冲优线**：在保底线基础上补全 **M4（多角色/多武器/蓝币养成/排行榜）** 与 **M5 完整版（后台联动弱网开关）**。

# knight-dev-mcp

Knight 仓库（Godot 客户端 + Go 服务端）的本地开发工作流 MCP server（stdio，Go 标准库零依赖）。注册于 `<repo>/.zcode/config.json` 的 `mcp.servers["knight-dev"]`（该文件属本机配置，不入库）。

## 工具

| 工具 | 作用 |
| --- | --- |
| `godot_verify` | Godot 客户端（C#/.NET）验证。`mode=check`：查 `project.godot` 的 config/features、Godot.exe 路径（常见安装目录自动解析，`godot_path` / `KNIGHT_GODOT_PATH` 可覆盖）、dotnet 与主/测试工程存在性、是否有 Godot 进程，秒回。`mode=compile`：`dotnet build` 主工程，只查编译。`mode=tests`：`dotnet test` 测试工程（隐含编译），**一条命令同时得出编译+测试双结论**——先从输出解析编译结论（命中 `error CS/MSB/NU/NETSDK` 即失败且测试必然未运行），再从 TRX 解析计数与失败明细；`test_filter` 转 `--filter`。**结果即收工**：TRX 一旦落盘（结论已定）给进程 10 秒宽限仍未退出即主动 Kill，以 TRX 判定结论（`earlyReap` 标注，退出码不代表测试结论）。**结论快照**：结束后同步写 `Knight-Client/.godot/last-godot-verify.json`（status/summary/计数/失败用例/日志路径），MCP 客户端超时丢响应时直接读该文件取回结论。检测到 Godot 进程仅提示程序集可能被占用（MSB3021/3027），不拒绝执行。 |
| `server_test` | 在 Knight-Server 跑 `go test -json`，返回通过/失败/跳过计数、失败用例输出、编译错误。服务端骨架（go.mod）落地前报错。 |
| `deploy` | 一键部署 Docker 栈（`Knight-Server/docker-compose.yml`，mysql + server 两服务）。默认 `up -d --build --force-recreate server`（日常改码更新路径）并轮询等待 server 的 `kcp listening` 日志；`service=all` 整栈首次部署。需要 Docker Desktop 运行中。 |
| `smoke` | 对容器服务器跑 HTTP 账号冒烟（走 `internal/httpapi` 契约）：`GET /healthz`（服务 + MySQL 连通）→ `POST /api/v1/register`（纳秒后缀唯一用户名）→ `POST /api/v1/login` 换 token → `GET /api/v1/users/{uid}`（Bearer 校验），默认 `127.0.0.1:37780`。部署后确认服务与数据库可用。 |
| `luban_export` | Luban 配置导出：`Knight-Design/Datas` 源表 → cs-bin C# 代码到 `Knight-Client/Scripts/Base/Gen/DataTable`（Gen 下另有 `Proto` 子目录放协议生成代码）→ **json 与 bin 双数据导出**（bin 是 `.tres` 的 `metadata/bin` 载荷来源，缺了客户端无法装载）→ json2tres 把两者合成 Godot **`.tres`** 后删除中间产物（tres = type=Resource 双载荷：`metadata/data` 行数组 + `metadata/bin` base64，是唯一数据产物；客户端 `load("res://DataTable/tbxxx.tres")` 直接取行数组，随 res:// 自动进 PCK 导出）→ 报告 git 变更。输出根由 `Knight-Design/path.txt`（默认 `../Knight-Client`）决定；`pathValidator.rootDir` = `Knight-Client/Textures`。gen_cli.bat/sh 经 `knight-dev-mcp.exe json2tres <json目录>` 子命令做同样转换。 |
| `consistency_check` | 只读预检三组：Luban 表名多处一致（`__tables__.xlsx` ↔ `Gen/DataTable/Tb*.cs` ↔ `Tables.cs` loader ↔ `LubanComponent.TableNames`（组件未创建时降级为警告）↔ `DataTable/tbxxx.tres` 产物 ↔ `Datas` 工作簿）、生成文件 `<auto-generated>` 头（递归扫 Gen 含 Proto/DataTable 子目录）、**实体场景存在性**（`EntityConfig` 场景列 `tscnPath`，兼容旧列名 `prefabPath`，必须指向 `Knight-Client/Prefabs/Entity` 下真实存在的 `.tscn`，不再认 .prefab 后缀）。 |
| `clients_launch` | 启动多实例 Godot (.NET/mono) 客户端用于联机自动化（1..4 个，默认 2 个 `["p1","p2"]`，起始端口 `19100`）。自动解析本机 Godot mono 二进制（`godot_path` → `KNIGHT_GODOT_PATH` → macOS `~/bin/godot-mono` / `Godot_mono.app` / PATH `godot-mono` 或 Windows mono 目录），按四宫格排布窗口并传入 `--instance-id=<id> --dev-agent-port=<port>`，日志落盘 `<repo>/.tmp/dev-clients/<id>.log`，持久化注册表 `<repo>/.tmp/dev-clients/registry.json`，并轮询 `GET /health` 直至就绪（超时附日志尾部）。 |
| `clients_list` | 列出所有受管 Godot 客户端实例并实时探测 `GET /health`，返回 `running` / `unhealthy` / `exited`、`id`、`pid`、`port`、`log_path`。 |
| `client_state` | 查询单个实例（`id="p1"`）或并行查询全部实例（`id="all"`）的 `GET /state`，返回 `scene`、`procedure`、`network`、`room`、`battle`、`ui` 等结构化 JSON。 |
| `client_act` | 向目标实例发送 `POST /action` 指令。支持单动作（`type` + `text`/`name`/`placeholder`/`move_x`/`move_y`/`aim_deg`/`attack`/`interact`/`duration_ms`）或批量 `actions` 数组顺序执行；`type="wait"` 在 MCP 侧本地等待 `duration_ms` 毫秒。 |
| `client_screenshot` | 调用目标实例 `POST /screenshot` 截屏保存为 PNG，默认路径 `<repo>/.tmp/dev-clients/screenshots/<id>_<timestamp>.png`。 |
| `clients_stop` | 停止指定实例或全部实例（省略 `id` 或 `id="all"`）：先发 `POST /action {"type":"quit"}`，最多等 2 秒后强杀残留 PID，并更新 `registry.json`。 |

## 构建

`go` 已加入用户环境变量；若某些进程未继承新 PATH，用绝对路径构建：

```bash
cd Knight-Tools/knight-dev-mcp
"/c/Program Files/Go/bin/go.exe" build -o bin/knight-dev-mcp.exe .
```

## 注册（重建 `.zcode/config.json` 时）

当前本机尚未注册（仓库 `.zcode/config.json` 不存在）；重建配置时按下文添加：

```json
{
  "mcp": {
    "servers": {
      "knight-dev": {
        "command": "D:/Godot/Knight/Knight-Tools/knight-dev-mcp/bin/knight-dev-mcp.exe",
        "args": [],
        "env": { "KNIGHT_REPO_ROOT": "D:/Godot/Knight" }
      }
    }
  }
}
```

`KNIGHT_REPO_ROOT` 可省略：server 会从 cwd / 可执行文件位置向上找含 `Knight-Proto/knight.proto` + `Knight-Server` 的目录。`KNIGHT_GODOT_PATH` 可选：Godot.exe 绝对路径，仅在 `godot_verify mode=check` 报告引擎路径时使用（compile/tests 只依赖 dotnet）。

## CLI 子命令（供 gen_cli.bat/sh 与手工调用）

```bash
knight-dev-mcp.exe json2tres <json目录>   # Luban 导出的 tbxxx.json → 同名 .tres（转换后删 json）
knight-dev-mcp.exe check                  # 一致性预检：有缺失/警告才逐行输出（[check][组名] 前缀），干净时不输出
```

注意：Luban 自身的 `path=unity` 校验（SpriteConfig.atlasPath 对 `Knight-Client/Textures`）是**非致命警告**——"找不到对应文件" 只打印不中断，导出照常产出；实体场景的 `.tscn` 存在性检查则由 `check`（即 consistency_check 的 entity_prefabs 组）承担。gen_cli.bat/sh 已按此顺序串联：Luban 导出 → json2tres → check。
